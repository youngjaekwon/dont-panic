# 0007. PG와 Redis는 인스턴스를 공유하고 논리적으로 분리한다

- 상태: 채택
- 날짜: 2026-11-15

## 맥락

서비스마다 DB 인스턴스를 띄우면 로컬과 k3s의 자원이 부족하다. 그렇다고 데이터를 공유하면 서비스 경계가 무너진다.

## 결정

- PostgreSQL 인스턴스 하나에 서비스별 database와 계정을 둔다.
- Redis 인스턴스 하나에 서비스별 키 prefix를 둔다.
- 서비스는 다른 서비스의 database나 Redis 키를 읽지 않는다. 다른 서비스의 데이터가 필요하면 gRPC로 묻거나, 이벤트를 받아 자기 저장소에 둔다.

## 결과

- 자원은 아끼지만, 인스턴스 하나의 장애가 모든 서비스에 영향을 준다.
- 계정을 분리해 두었으므로 나중에 인스턴스를 나눌 때 서비스 코드는 연결 문자열만 바뀐다.
