# 0001. 언어 중립 모노레포, 서비스별 툴체인

- 상태: 채택
- 날짜: 2026-11-15

## 맥락

한 제품을 이루는 도메인 서비스들을 MSA로 만든다. 서비스끼리 서로 호출하고, 언어가 섞일 수 있다. 출발점은 쿠폰 서비스 하나다.

## 결정

- 저장소 하나에 모든 서비스, 계약, 인프라를 둔다.
- 루트는 특정 언어가 차지하지 않는다. 서비스마다 자기 툴체인과 lock 파일을 가진다(Python은 `pyproject.toml` + `uv.lock`, Go라면 `go.mod`).
- 새 서비스는 기존 서비스 폴더를 복사해서 시작한다. 서비스 공통 프레임워크 라이브러리는 만들지 않는다.
- 서비스는 다른 서비스의 코드를 import하지 않는다. 공유하는 것은 `proto/` 계약뿐이다.

## 결과

- 계약 변경과 그 계약을 쓰는 서비스 변경을 한 커밋에 담을 수 있다.
- 언어를 추가해도 기존 서비스의 빌드에 영향이 없다.
- 공통 코드(부트스트랩, 설정)는 서비스마다 중복된다. 세 번째 서비스에서도 같은 코드가 반복되면 추출을 다시 검토한다.

## 검토한 대안

- **uv workspace(루트 lock 하나)**: 언어가 섞이면 루트를 Python이 차지하게 되어 기각했다.
- **서비스별 저장소**: 계약 변경을 여러 저장소에 나눠 반영해야 해서 기각했다.
