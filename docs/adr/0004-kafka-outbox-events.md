# 0004. 비동기 통신은 Kafka, 발행은 outbox

- 상태: 채택
- 날짜: 2026-11-15

## 맥락

도메인 서비스들이 서로 호출한다. 즉시 답이 필요 없는 "일어난 사실"까지 동기 호출로 처리하면 서비스 간 결합과 장애 전파가 커진다.

## 결정

- 즉시 답이 필요한 호출은 gRPC로, 사실의 통지는 Kafka 이벤트로 한다.
- 이벤트 스키마도 protobuf로 정의한다(`proto/<서비스>/v1/events.proto`). 토픽 이름은 `<서비스>.<이벤트>.v1`이다.
- 발행은 outbox 패턴으로 한다. 비즈니스 변경과 같은 PG 트랜잭션에 outbox row를 쓰고, relay가 Kafka로 보낸다.
- 소비자는 이벤트 id로 중복을 걸러 멱등하게 처리한다.
- 여러 서비스에 걸친 분산 트랜잭션은 만들지 않는다. 이벤트와 보상 동작(saga)으로 처리한다.

## 결과

- 이벤트 유실 없이 발행할 수 있지만, 그 대가로 relay를 운영해야 한다.
- Kafka는 k3s 위에서 메모리를 많이 쓴다. 로컬 자원이 부족하면 NATS JetStream이 대안이다.

## 검토한 대안

- **NATS JetStream**: 가볍지만, 포트폴리오 목적상 인지도가 높은 Kafka를 택했다.
- **Debezium CDC**: outbox relay를 대신할 수 있지만 지금 규모에서는 과하다.
